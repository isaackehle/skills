# JD Analysis Method

## Reading requirements

- **Required:** "must," "required," "X+ years," anything in a Requirements or Qualifications list.
- **Preferred:** "nice to have," "bonus," "preferred," "familiarity with."
- **Implied:** what the responsibilities need even if it isn't listed. "Own the roadmap" implies planning and
  stakeholder work. "Work with customers on site" implies travel.

Years-of-experience requirements are a level signal, not a hard filter. Record them as stated.

## Keywords

- Use the JD's spelling ("Postgres" vs "PostgreSQL", "K8s" vs "Kubernetes"). Note both forms when the resume uses the
  other one. ATS matching is often literal.
- Deduplicate synonyms into one keyword with its variants listed.
- Domain terms (payments, HIPAA, FedRAMP, PCI) count as keywords.
- Generic soft skills ("team player") don't count toward coverage.

## Coverage

Coverage = matched keywords / total keywords, required weighted 2, preferred weighted 1.

- **Current:** matched by the base resume as it is.
- **Ceiling:** matchable using only direct or adjacent inventory evidence.
- The profile's coverage target (often 75–80%) is a goal, not a quota. If the ceiling is below target, report it. The
  answer is a different role or an honest gap, not a stretched claim.

## Scope signals

| Signal in the JD                                  | Reads as                         |
| ------------------------------------------------- | -------------------------------- |
| "set technical direction," "across teams," "org"  | Principal / Staff+ scope         |
| "own [one service/product]," "mentor juniors"     | Senior / Staff scope             |
| "implement," "work on tickets," "under guidance"  | Senior or below                  |
| "customer-facing," "on site with customers"       | Forward-deployed shape           |
| "fast-paced," "wear many hats," "hit the ground running" | Pace risk, probe in screen |

A title above the scope (Principal title, single-team scope) or below it (Senior title, org-wide scope) is a mismatch.
Flag it either way.

## Evidence classes

- **Direct:** the inventory shows the same thing.
- **Adjacent:** the inventory shows a close relative. The bridge has to be stated in one line and has to hold up when
  an interviewer asks about it ("event-driven with SNS/SQS" → "Kafka" is adjacent; "used an API" → "designed APIs" is
  not).
- **Gap:** nothing. Gaps get a gap answer for interviews, not a resume claim.
